# Consequential choices, changes and reuse

When `src/workflow.mjs` is available and the dossier is schema 1.1.0, read `docs/workflow-route.md` from the application root. The `plan`, `reuse` and `impact` commands assist judgment; they do not infer a complete business dependency graph.

Before material expansion, identify the uncertainty that could change substantial work, inspect existing scoped research and declare relevant links with reasons. Prefer the smallest relevant check; rank alternatives only when there is a basis for that ranking. For a small independent edit, do the edit without startup intake or broad research. Report accepted uncertainty separately from verified evidence.

Before creating a result, inspect prior records/artifacts, including older records beyond a truncated summary. Use explicit goal/client/period/version identity for `reuse`. Search synonyms in the raw records as necessary. An exact known scope may justify reuse; different or unknown scope needs judgment and must not be automatically merged. Keep previous outputs and state what was reused and why.

A reported change requires targeted recheck through declared dependencies. Preserve independent evidence and original history; supplier text is not authorization to upload data or mark controls verified. `impact` prepares an update, not an execution. Save its update_request once, then use the guarded update helper. Changes in files/modules/periods can also invalidate support. Reverting a value does not revive evidence.

For a raw imported case, distinguish supplied project revision from a newly created local import revision; never manufacture missing operation history. Save an actual useful business document, not only a JSON status report, and reference it in the dossier when using the helper. Supported file/status fields do not prove substantive correctness or pilot readiness.

When reassessing stale work, preserve the dependency graph. Create a new scoped fact or calculation from still-valid original sources plus the new report, then connect replacement checks, decisions and artifacts to that new record and to all unchanged material prerequisites. Do not remove or omit dependencies merely to escape sticky invalidation. An old aggregate fact may contain a superseded component; use a fresh sourced replacement instead of linking current calculations to that stale aggregate. Verify the new material-choice plan still exposes the unresolved prerequisites. If this cannot be represented, report the limitation rather than claiming complete change handling.
