# Complete a learning loop

A loop connects a question, planned conditions, sourced observations, your interpretation and a reasoned change. It does not automatically validate a business idea.

1. Prepare an offer and an experiment card. Record the question, audience, method, observation to seek, decision rule and effort/stop conditions before execution when possible. A local timestamp does not independently prove chronology.
2. Declare the start against the exact plan version. Record actual source material only when it exists and you may store it; otherwise leave the question open. Fictional practice belongs in a separate practice project.
3. In Source inbox, preserve original content, context, limitations and attribution. Review duplicate warnings. Add a sourced experiment observation with its date and keep your interpretation separate.
4. Compare observations with the original conditions. In the experiment review, choose continue, adapt, park or investigate; explain the reason and proposed implications and select affected offers/tasks. This saves a proposal, not the changes.
5. Open the affected current offer, edit only intended sections, and explain the decision in the change reason. Review the complete preview and confirm a new version. Earlier text and experiment rules remain available. In the section editor, optionally select a current Adapt review that explicitly targets this offer. The preview links that review as the changed section basis; it remains a proposal. Stale, unrelated or unavailable reviews cannot be attached. No review is selected automatically.
6. Reopen the project. Read the original source, review and both offer versions. A changed target can flag the old review for context review: it still records the historical proposal, not approval of all later changes. Return to open learning questions and choose the next uncertainty.

## Repeatable synthetic reference

Run from the application directory with a new destination outside it:

```powershell
node examples/demo-learning-loop.mjs C:/path/to/new-private-learning-demo
```

This writes a fictional practice dossier and private retry bundles, refuses an existing destination and makes no network/model calls. The output lists IDs for the original offer, complete experiment plan, start, invented source, observation, review and revised offer. The revised outcome explicitly links the review as its basis while remaining a proposal. All other offer fields stay unchanged. The example deliberately contains polite interest, no recent problem, a working alternative and no purchase agreement; it never labels that demand.

`node --test tests/learning-loop.test.mjs` checks the persisted full chain, historical values, unchanged unrelated fields, source and rule identity, linked revision reason, no task/evidence promotion and refusal to overwrite the same destination. This is a technical reference, not a real research result or an AI evaluation. Real-user use remains separate; browser verification of the review selector must also be recorded.


## Read the failed assumption, not just the revised offer

The original proposed outcome assumes that replacing the handover process is worth investigating. In the fictional note, the existing checklist works, no recent problem is recalled and no purchase was agreed. That contradicts the example's justification for replacement; polite interest does not rescue it. The original decision rule therefore leads to Adapt, and the offer changes from replacement to investigating one recent handover.

Inspect the original offer, original experiment rule, source, observation, review and revised offer in that order. Unchanged delivery and exclusions show that the review did not silently rewrite the whole service. The task remains open and demand remains unknown. This is a failed assumption within an invented scenario, not a falsified market claim: the example intentionally adds no canonical fact or evidence record and does not label an assumption verified merely because a test passed.

Try the counterexample: if the source described a concrete recent loss, the same automatic conclusion would be unjustified. Record a new observation and explicit review; do not edit the old source or replace the historical rule. Both versions must remain readable. The reference test checks this chain's stored identities and proposal status; it does not simulate actual participants.
