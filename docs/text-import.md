# Import plain text and limited Markdown

Import preserves the exact supplied Unicode text (including line endings), format choice, title and source fingerprint as a separate immutable project artifact. It does not turn prose into business fields, facts, evidence, completed tasks or executable instructions. Choose up to 20 existing project records as context links; those links capture the record fingerprint at import and later show unchanged, changed or missing status. They are not proof or automatic workflow dependencies.

Only readable text up to 64000 UTF-8 bytes is supported, with a title up to 200 characters. Empty/blank, malformed Unicode and binary control characters are rejected. Plain text and limited Markdown are shown literally in the exact preview: heading/list markers are preserved; tables, HTML, images and code stay literal. No parser executes content, no links/images are fetched, and no command, macro, script or instruction from an import gains authority. Unsupported-looking syntax produces a notice, not silent removal.

The local authenticated API exposes `text-imports` (`ref`), `text-import-read` (`ref`, `artifact_id`), `text-import-preview` (`ref`, `revision`, `sha256`, `document`) and `text-import-save` (`ref`, `preview`, `confirmed:true`). The document contains exactly `title`, `format` (`text` or `markdown`), `text` and `record_ids`. Preview does not write. Confirmed save uses the existing revision-checked artifact transaction and idempotent receipt; archived projects remain read-only. Only the import-preview route allows a 512 KiB JSON request to accommodate escaping within the 64000-byte text limit; other request limits remain unchanged.

Up to 200 imports are supported. Corrupt or inconsistent history refuses listing/reading rather than hiding failures. Original files are not modified; association changes do not rewrite old imported text. In the browser, open **Imported text**, choose **Import text or Markdown**, enter a title, paste source or select a UTF-8 file, and choose optional context links. Review the exact preview and confirm saving. Read-back shows the original source and association status. Unsaved changes guard project navigation and closing; discard is explicit, and unsaved imports are excluded from recovery copies. File decoding rejects malformed UTF-8 and retains BOM/line endings until the text is edited; editor changes become the selected source and may normalize line endings. The original file is never modified. This is not PDF/Word/HTML document conversion, full Markdown rendering or an AI interpretation of imported instructions.

Verification limitation: browser automation cannot currently set file inputs because the extension lacks file-URL access. No browser permission was changed. Paste/preview/link/save/read-back was exercised in Edge; file decoding and BOM/CRLF retention are covered by helper tests, but the native file-selection flow remains unobserved.
Import preparation now compares retained sources: identical title/format/text and current context fingerprints are skipped with a reuse message; identical text with changed metadata or context is labelled changed context; an existing title with different text is flagged as conflicting. Changed/conflicting imports remain separate immutable sources after explicit confirmation, never overwrites. Context link ordering does not create a difference. Dry-run helper previewTextImport performs no writes. This is single-source local comparison, not remote identity reconciliation or batch synchronization.
