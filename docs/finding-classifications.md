# Reviewing findings against assumptions

Each saved research finding starts unreviewed. A user can explicitly classify it as supporting, contradicting or inconclusive, with a reason and contributor alias. Inconclusive is a judgment, not the default for missing review. These labels never change an assumption's assertion, evidence status, task completion or workflow approval.

Each immutable judgment binds the exact finding fingerprint and current assumption snapshot. A later judgment keeps the earlier version and reason. If the assumption or source changes, the prior judgment moves to a separate needs-review group rather than continuing to count as current support. A fresh judgment requires an unchanged readable source and binds the then-current assumption. Original finding context and repeated-fragment links remain visible in the data; classifications do not establish independent observations or representative research.

The API provides grouped findings and guarded preview/save. Browser controls show the three reviewed groups side by side (stacked on narrow screens), separate unreviewed/needs-review lists, exact fragment/current/original assumption context, judgment history, and explicit preview/confirmation. Edge checks cover explicit Inconclusive classification, edit-triggered confirmation reset and saved read-back without assumption promotion; remaining history/stale-state and responsive checks are pending. Bounds: 1000 classification versions per project, 8000 UTF-8 bytes for a reason, 800 for an alias and 64 KiB per saved record. Strict shapes, history ancestry, project/artifact fingerprints, archive/current-state guards and explicit confirmation apply.

Source removal includes every classification version for a removed finding, including its assumption snapshot, reason and alias. Verified local retry content is removed by the same existing operation; unrelated and external copies retain the documented exclusions. Tests use fictional data only. Neither synthetic checks nor a user's classification constitute business validation.

Coverage reports stored research links, distinct fragment identities and source records per assumption, plus counts for all five review groups. Two passages in one source remain two fragments but one source record. Reusing a fragment against another assumption does not establish another independent observation. Counts do not establish participants, independent origins or representative market evidence. Opposing and minority judgments remain visible without a majority-vote conclusion. Source relations now list each source record and its finding IDs. Readable unchanged conversations expose their recorded inbox context source; this is possible dependence, not verified origin. A missing relationship does not establish independence, and damaged conversation content makes the relationship unavailable. Pattern/exception review remains planned.

Conversation history is validated as a whole. A damaged conversation record can make other conversation-derived relations unavailable until the history is restored; the overview does not infer relationships from an unvalidated history.


## Applicability of a judgment

New browser judgments ask for audience, situation and period. Each is explicit user text (at most 2000 UTF-8 bytes) or unknown when left blank. The exact preview, current judgment and immutable history display this scope. Legacy v1 records remain unchanged and display Not recorded; v2 records retain the supplied scope. Revising a judgment preserves earlier scope, and no scope is copied to another assumption, even when it references the same fragment. A scope describes applicability, not verified representativeness or a promotion of the assumption. Editing a scope field invalidates the existing preview confirmation. Source removal covers these fields along with the rest of each linked classification. M4-10 Edge checks cover exact scoped preview/save/read-back, edited-scope confirmation reset, legacy/new history and 390 × 844 layout without horizontal overflow. Source and clean-install suites each pass 360 tests before the subsequent CSS-only wrapping correction.
