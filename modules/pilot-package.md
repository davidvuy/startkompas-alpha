# Connected pilot package — draft 0.1.0

Use after customer-learning and scoped conditions work identifies a candidate pilot. Reuse the current brief, evidence and conditions; do not regenerate them just to fill a package. This procedure prepares an internally connected draft, not a launch approval. Qualified content/coherence/coverage review remains required. Missing reviews, customer evidence and actual agreements stay open.

1. Identify one project, milestone, client scope, period, version and known facts. Link source artifacts and distinguish case facts, proposals and unknowns. Keep price, available experiment budget and delivery costs distinct.
2. Assemble an index linking: pilot brief, relevant conditions, same-period costs with explicit exclusions, product acceptance demonstration, unsent recruitment copy and support/exit plan. An unknown cost is not zero. Recruitment promises must match the actual draft maturity and evidence. Do not claim proven savings, compliance, customers, service levels or limited availability without evidence.
3. Connect checks to source facts and current artifacts. At minimum review customer outcome, price/cost/budget, data/provider conditions, rights, acceptance and support. Explain each dependency. Record unresolved review scope and conflicting views. If using the schema1.1 helper, use existing records/links and guarded attachments; never create a second competing canonical state. Ordinary documents remain an allowed simpler route.
4. For a changed provider/data scope/price/customer/commitment, use impact analysis to identify affected costs, terms, acceptance or support; preserve unaffected learning and historical versions. Rechecking an attachment hash only proves bytes. A technical consistency check does not satisfy legal, commercial or security review.
5. Save and read back the package. Give the founder the next feasible step and all urgent blockers. Keep unsent copy unsent absent explicit outreach authority. No contract signature, invoice, external upload, publication or purchase follows from preparation alone.

Reviewer handoff: exact package revision and source facts; requested professional competence; sections in/out of scope; source, interpretation, applicability and coverage decisions separately; conflicts/dissent; changes required; date and evidence artifact. A blank review template is not review performed.

## Executable assembly for an existing schema1.1 dossier

Use node src/pilot-cli.mjs prepare <private-project-dir> <request.json>. The request shape is in examples/pilot-package-request.json (synthetic only). Read the existing dossier first; supply expected_revision, a new operation_id, actual date, language nl/en, a scoped description or null, and selected sections. Each section has kind (brief, conditions, costs, acceptance, recruitment, support), summary (supplied draft text or null) and record_ids for the existing basis. Missing sections/unknown summaries remain visibly unfinished. Do not invent facts to populate them.

The command returns content (one Markdown draft), sections with recorded status/review flags, artifact_id and update_request. It is read-only. Save content as exact UTF-8 bytes and update_request as JSON outside the application; then run node src/core-cli.mjs attach <private-project-dir> <saved-update-request.json> <saved-content.md>. Retry those same saved files after an uncertain outcome; do not regenerate with the old operation ID. Read back the canonical artifact path/hash/revision before claiming it saved.

This adds one versioned artifact, an event and dependency links to the selected records. It does not rewrite source documents, complete checks, calculate unknown costs, send recruitment or approve the pilot. Later changes to linked facts/sources/records propagate review requirements through the existing workflow graph. A new authorized package version uses a new operation ID and preserves earlier artifacts. A reused record reference retains its original scope/status; a selection can still be incomplete and requires review. Missing/tampered references are flagged without reading their contents into the draft.
