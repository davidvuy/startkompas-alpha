# Code of conduct

## What is expected

Be straightforward and civil. Assume the other person is trying to help.

- Keep discussion on the work: the code, the instructions, the sources, the evidence.
- Disagree about substance, not about people. "This source does not say that" is useful. "You clearly know nothing" is not.
- Accept a correction when it is right, and say so plainly.
- Respect the project's core discipline: do not present an unverified claim as verified, and do not strip someone's recorded uncertainty to make an answer look cleaner.

## What is not acceptable

- Harassment, insults, or demeaning comments about a person or a group.
- Sexual attention or imagery.
- Publishing someone's private information.
- Deliberately posting false sources, fabricated review attributions, or invented legal, tax or security claims. In this project that is a conduct problem, not only a technical one, because people may act on it.
- Posting someone else's private dossiers, customer data or credentials.

## Scope

This applies to issues, pull requests, discussions, commit messages and any other space maintained by this project.

## Reporting

This project is maintained by one person and uses **GitHub-only contact**.

- For conduct problems: open an issue, or use GitHub's own abuse reporting if the matter involves the maintainer or is unsafe to post publicly.
- For security vulnerabilities, use [private security reporting](https://github.com/davidvuy/startkompas-alpha/security/advisories/new) instead.

**There is no response-time guarantee and no second responder.** That is an honest limitation of a single-maintainer alpha, not a policy. If something needs a guaranteed response, GitHub's own reporting channels are the better route.

## Consequences

The maintainer may edit, hide, lock or delete contributions that breach this document, and may block accounts. Where a decision is explained, the explanation is kept with the thread rather than sent privately.
